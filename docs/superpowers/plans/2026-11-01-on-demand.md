# On-demand Kinect capture implementation plan

User wants regular-camera behavior: physical capture only while an application
uses a camera. Installed v4l2loopback 0.15.4 supports client-usage events; an actual
read-only event subscription succeeded. libfreenect2 supports stream stop/start.

Keep loopback producers attached and advertise capture using blank bootstrap
frames. Subscribe to client-usage events with SEND_INITIAL; kernel events track
capture STREAMON/STREAMOFF (including close), rather than file opens used for
enumeration. Start one physical Kinect session when any enabled camera streams;
stop and close after the last consumer leaves and a configurable 1000ms grace.
All configured physical streams run together during a session; IR/depth share
hardware. Clear output buffers on idle so old images are not reused on wake.
Idle uses no physical Kinect context. The adapter remains electrically powered.

CLI gets --on-demand and --idle-timeout-ms; service/example default to on-demand,
CLI continuous mode remains available for diagnostics. Synthetic mode also
honors demand so output lifecycle is testable without hardware. Unsupported
event APIs fail clearly, without silently capturing continuously. Wake-up may
take seconds; Howdy may need a longer authentication timeout. No PAM/model edits.

Execute inline under existing delegation of routine choices. Test before code.

Verification boundary: local user cannot sudo noninteractively, so testing the
physical sensor requires the user to stop the existing service. No root service
will be silently replaced. Sensor LED/emitter physical behavior needs observation;
stop/close calls and absence of capture work can be verified programmatically.

Completed verification: all eight CTest suites pass; physical IR wake/idle/wake
passed with first usable frames at 1.295s and 1.080s, respectively. USB stop/close
was logged after each consumer, with no spontaneous idle wake. No images saved.
Review's queue-size finding was fixed by querying actual allocated buffers;
the live-test ENOENT empty-event behavior was reproduced in fixtures before fixing.
